## 1. Загальна структура проекту
Проект ініціалізовано та налаштовано згідно з вимогами:

## 2. Реалізація ООП парадигм
У файлі `agent.py` реалізовано систему збору погодних даних з демонстрацією всіх 4-х парадигм ООП:

1. **Абстракція:** Створено абстрактний базовий клас `Sensor` (за допомогою модуля `abc`) з абстрактним методом `read()`, який визначає загальний інтерфейс для всіх типів датчиків.
2. **Наслідування:** Створено класи `TemperatureSensor` та `HumiditySensor`, які успадковують базові атрибути (`name`, `unit`) від класу `Sensor`.
3. **Інкапсуляція:** У класі `WeatherStation` датчики зберігаються у приватному списку `__sensors`. Додавання нових датчиків та доступ до них відбувається безпечно через публічні методи класу (наприклад, `add_sensor`).
4. **Поліморфізм:** Метод `report()` у класі `WeatherStation` ітерується по списку всіх датчиків і викликає метод `read()`. Завдяки поліморфізму кожен об'єкт (термометр чи гігрометр) повертає власне випадкове значення у відповідному форматі, використовуючи єдиний інтерфейс виклику.

## 3. Налаштування AI-Агента
* **Інструмент (Tool):** Створено функцію `get_weather(city)`, яка ініціалізує об'єкт `WeatherStation` для вказаного міста, підключає до нього `TemperatureSensor` та `HumiditySensor`, після чого викликає метод `report()` для отримання зведених даних (температура, вологість, погодні умови).
* **Агент:** Налаштовано AI-агента (Метеорологічного помічника) за допомогою фреймворку Google ADK. Агент використовує інструмент для отримання даних та надає українською мовою рекомендації щодо одягу чи необхідності брати парасолю.
